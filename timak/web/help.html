1. What Timak does

Time Machine is the backup tool built into every Mac. Over the years it fills disks with copies of everything: your documents and photos, but also macOS itself, all your applications, and caches, which are files your Mac can make again at any time.

Timak reads those old backups and copies only your own files into a new place called the archive: documents, photos, music, mail, projects, as they were on each backup date. It leaves out macOS, the applications and the caches. A file that did not change from one backup to the next is stored only once. The result is usually much smaller than the backups it came from.

The archive is made of ordinary folders. You can open it in the Finder and copy files out of it like from any other folder. You do not need Time Machine, or even Timak, to read it later.

Your backups are safe. Timak only reads your old backups. It never changes or deletes anything in them.

2. A few words you will see

Backup disk
The external disk Time Machine used to save backups on. Sometimes the backups are instead inside one big file ending in .dmg, .sparseimage or .sparsebundle: that is a disk image, a whole disk stored in a file.
Snapshot
One backup, as it was at one date and time. A backup disk usually holds many snapshots: one per hour, day or week.
Source
What Timak reads from: a backup disk, a disk image, or a folder copied out of a backup.
Archive
What Timak writes: one folder per Mac, and inside it one folder per snapshot, named after its date, such as 2019-05-12-093000 (12 May 2019 at 09:30:00).
Volume
A disk as the Mac shows it, with a name: “Macintosh HD”, “Data”, “My Passport”… A backup can hold several volumes.
Rules
The list that tells Timak what to keep and what to leave out. Timak comes with good rules already; you only need your own if you want to change them.
Dry run
A rehearsal: Timak shows what it would do, but does nothing. Always safe.
Hard link
The trick that saves space: when a file is the same in two snapshots, the second snapshot does not get a copy, it gets a second name for the same file. Both folders show the file, but it is stored once.

3. Before you start

What you need

  • The old backup: the Time Machine disk, plugged in, or the disk image file.
  • A disk for the archive, with enough free space. The archive needs about the size of your own files, plus what changed between backups. If your home folder was 200 GB, plan for 250 to 400 GB. A Scan tells you more precisely before anything is written.
  • Time. Extracting a large backup can take hours, or a whole night. It can be stopped and continued later.

Do not use the disk Time Machine is still using. If the backup disk is still chosen in System Settings › General › Time Machine, remove it there first (or turn Time Machine off) so that it does not start a new backup, or delete old ones, while Timak is reading.

Give Timak “Full Disk Access” (once)

macOS protects Time Machine backups. Without this permission, Timak cannot look inside them.

  1. Open the Apple menu › System Settings…
  2. Click Privacy & Security in the list on the left, then Full Disk Access on the right.
  3. Find Timak in the list and turn its switch on. If it is not in the list, click +, open the Applications folder, choose Timak, and click Open.
  4. macOS asks for your password: type the password you use to log in to your Mac.
  5. Quit Timak (⌘ Q) and open it again.

At the top right of the Timak window, a green Full Disk Access label means it worked.

The password when Timak starts

When it opens, Timak asks for your Mac password. It needs it to open some kinds of backups (APFS backups from macOS 11 Big Sur and later) and to keep the owner of each file. If you click Cancel, Timak offers to start without it; that is fine for most older backups.

Keep the Mac awake

Plug your Mac into power. If it goes to sleep, the work stops. In System Settings, under Battery (or Energy), turn on the option that prevents automatic sleeping when on power, for the time of the extraction. The screen may turn off; that is fine.

4. The Timak window

  • At the top: the Timak name and version, the Help button that opened this page, and three labels. Green means good: running as root (the password was given), Full Disk Access, and rsync 3 (a tool Timak uses to copy). Point at an orange label to see what to do about it.
  • Backups and archive: where you say what to read (Sources), where to write (Archive folder), and, if you have one, your own Rules file. More options holds settings most people never need.
  • Four tabs:
    • Snapshots: what Timak found in your backups.
    • Rules: view or edit what is kept and left out.
    • Run: the buttons that do the work, and below them a box showing progress.
    • Archive: what is already in your archive.

5. Your first archive, step by step

  1. Plug in your disks. Connect the old backup disk and the disk that will hold the archive. Wait until both show up in the Finder sidebar.
  2. Add the backup as a source. In Sources, click Browse…, go to the backup disk, and choose it. On most backup disks, choose the disk itself or the Backups.backupdb folder on it. If your backup is a disk image file, choose that file. Click Add.
    Shortcut: you can also drag the disk or the file from the Finder onto the Timak window.
  3. Choose where the archive goes. In Archive folder, click Browse…, go to the archive disk, and type a short new name such as tm or old-backups. The name must not exist yet: Timak creates it.

    On most modern disks (formatted as APFS), Timak does not make a plain folder but a disk image named, for example, tm.sparsebundle. It is a single file-like item that holds the whole archive and grows as needed. You keep using the name tm in Timak; it finds the image by itself. To look inside it in the Finder, double-click it.

  4. Look at what is there. Click the Snapshots tab, then List snapshots. You see each backup date, the Mac it came from and its volumes. Volumes marked to be extracted are the ones holding your files. If you see an orange warning about a volume being skipped, read it: it says how to keep that volume if it matters to you.
  5. Rehearse with Scan. Open the Run tab and click Scan. Nothing is written. At the end, Timak shows how much would be kept, and how much each rule leaves out. If something you care about is left out, see Rules before going on.
  6. Extract. Click Extract. A line appears for each snapshot, and the bar shows progress. You can keep using your Mac meanwhile, but do not unplug the disks.

    Need to stop? Click Stop. Later, click Extract again with the same settings: Timak continues where it stopped. Snapshots already finished are not done again.

  7. Check with Verify. When Extract says done, click Verify. Timak compares the archive with the backup and lists any difference. A few unreadable files (often system files locked by macOS) are normal. The full report is saved in the archive, in a file ending in .timakreport.
  8. Look at the result. Open the Archive tab and click Refresh: you see each Mac and each snapshot with what was copied. In the Finder, open the archive (double-click tm.sparsebundle if it is a disk image) to see the dated folders.

Keep the old backup disk until Verify is done and you have looked at the archive yourself. Only then decide whether to reuse that disk.

6. Adding more backups later

An archive can hold backups from several disks and several Macs. To add another backup, choose it as the source (remove the old one with the ✕ next to it), keep the same archive folder, and click Extract. Snapshots already in the archive are skipped, and unchanged files are linked to the previous snapshot, so the archive grows only by what is new.

If the same Mac had a different name in an older backup, or its disk was called differently, use Rename machines or Rename volumes in More options so that everything lines up under one name. Afterwards, Dedupe (see below) catches files that are the same but came from different disks.

7. Getting your files back

  1. Plug in the archive disk and open it in the Finder. If the archive is a .sparsebundle, double-click it: it appears in the Finder sidebar like a disk.
  2. Open the folder of the Mac, then the folder of the date you want, for example 2019-05-12-093000.
  3. Inside, the folders look like on that Mac at that date: Macintosh HD › Users › your name › Documents…
  4. Drag the files you want to your Desktop or anywhere else. This copies them; the archive is not changed.
  5. When done with a disk image, eject it: click the ⏏ next to its name in the Finder sidebar.

Looking for a file but not sure of the date? Open the newest snapshot first: files that never changed are in every later snapshot too.

8. Making the archive smaller

These buttons are all in the Run tab.

See what takes the space

  • Kinds shows how much space mail, photos, videos, music, documents and so on take. Nothing is changed.
  • Biggest lists the biggest files and folders. Next to each folder, it suggests the rule that would leave it out. Nothing is changed.
  • Disk usage gives the real size of the archive.

Remove what you do not want: Prune

Say Biggest shows an old virtual machine of 60 GB you never want back. You can tell Timak to leave it out and remove it from the snapshots already extracted:

  1. Add a rule for it in the Rules tab and click Save (see Rules). Your rules file must be set in Rules file at the top.
  2. In the Run tab, leave Dry run ticked under Prune, and click Prune. Timak lists everything it would remove, and how much space that would free.
  3. Read the list carefully. If it is right, untick Dry run and click Prune again. Timak asks you to confirm.

Prune really deletes from the archive, and this cannot be undone. Something removed can only come back by extracting again from the original backup. Always read the dry run first.

Merge identical files: Dedupe

Dedupe finds files that are exactly the same but stored twice, for example a photo you moved to another folder, or backups of the same Mac from two disks, and keeps one copy. Nothing you see changes, only the space used. Run it with Dry run ticked first to see how much it would save.

9. Rules: choosing what to keep

The built-in rules keep your home folder and leave out applications, macOS, caches, and similar files that can be made again. Most people never need to change them.

Making your own rules file

  1. Open the Rules tab and click Start from built-in rules. The text of the rules appears.
  2. At the top of the window, in Rules file, click Browse…, pick a folder such as your Documents folder, type a name such as my-rules.toml, and confirm.
  3. Change the text (see the examples below) and click Save. Timak checks the text and tells you if something is wrong.

Reading and writing a rule

Each rule is one line between quotes, ending with a comma. A - means “leave out”, a + means “keep”. The first rule that matches a file decides.

RuleMeaning
"- ~/Movies/",Leave out the Movies folder of every user. ~ means “each home folder”.
"- ~/Downloads/",Leave out the Downloads folders.
"- *.iso",Leave out every file whose name ends in .iso. * means “anything”.
"+ ~/Library/Mail/",Keep the mail, even if a rule further down would leave it out.

A / at the end means “a folder”. When a folder is left out, everything inside it goes too: a + rule cannot bring back a file inside it. After changing the rules, run Scan to see their effect before extracting. Rules only apply to snapshots extracted afterwards; to apply them to snapshots already in the archive, use Prune.

10. Keeping a second copy

Any disk can fail one day. Once your archive is complete and verified, copy it to a second disk and keep that disk somewhere else.

  • If the archive is a .sparsebundle, eject it first, then drag it in the Finder to the other disk. It is one item, so the copy keeps everything as it is.
  • If the archive is a plain folder, a Finder copy would store every snapshot in full and could take many times the space. Ask someone comfortable with the Terminal to copy it with rsync -aH, which keeps the space-saving links.

11. When something goes wrong

What you seeWhat to do
“Operation not permitted”, or an orange no Full Disk Access label Give Timak Full Disk Access (see above), then quit and reopen Timak.
An orange rsync 3 missing label Timak needs a copy tool installed with Homebrew. Ask someone to run brew install rsync in the Terminal.
“timak is not running” or “not answering” Click Start timak. If it keeps happening, use the Server menu › Show Server Log and send the log to whoever helps you.
Extract stopped (disk unplugged, Mac went to sleep, you clicked Stop) Plug everything back in and click Extract again with the same source and archive. It continues.
The archive disk is full Stop, free space or choose a bigger disk. Kinds and Biggest show what to leave out.
A volume is “SKIPPED” It holds no home folders, so Timak does not know it should keep it. If it matters, the warning gives the line to add to your rules file.
A warning about case (README and readme) The backup tells apart names that differ only by capital letters, the archive disk does not. Let Timak make the archive as a disk image on an APFS disk, which avoids it.
Some files are listed as unreadable Usually locked system files, of no use to you. If they are your own files, check Full Disk Access and that the password was given at start.
The window shows nothing or seems stuck Use View › Reload Page (⌘ R). A running command is not interrupted.

12. What Timak will and will not touch

  • Your old backups: only read, never changed. Disk images are opened read-only.
  • Scan, Verify, Biggest, Kinds, Disk usage, Compare, and any Dry run: only read. They may save a small report file in the archive.
  • Extract: adds new snapshots to the archive. It never changes a snapshot that is finished.
  • Dedupe without dry run: replaces identical copies by links. Your files and their content stay.
  • Prune without dry run: deletes from the archive what your rules now leave out. This is the only button that removes your data, and it asks first.

Quitting Timak while a command runs: Timak asks whether to stop it or let it finish in the background. Opening Timak again reconnects to it.
